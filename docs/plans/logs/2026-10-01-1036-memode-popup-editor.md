- `Phase 2 > 6` — 「全画面アプリの上に出るか」を自走で見られる項目に入れている / 全画面の Space を作るには、操作する側のプロセスにアクセシビリティの許可が要る。重なり方を画面で確かめるには画面収録の許可も要る。`--snapshot` はパネルだけを撮るので、全画面アプリと重なっているかは判定できない。このままだと AI が Phase 2 > 6 で止まるか、確かめずに済ませてしまう / この項目は人間の確認（Phase 2 の確認 > 1）に移す。優先順では一番下なので、そこで見れば足りる。NSOpenPanel が前に出るかは、`CGWindowListCopyWindowInfo` で重なり順を取れば自走で判定できる（ウィンドウの持ち主と順番だけなら許可は要らない）と書いておく
- `Phase 6 > 4` — URL に入れるパスを percent-encode する方法が決まっていない / パスに空白・日本語・`#`・`&`・`?`・`%` が入ると、URL が壊れるか、別のパスとして解釈される。シェルには素直なエンコードの手段がない。`python3` は CLT 頼みで当てにならない / エンコードの手段を決める（例: `osascript -l JavaScript -e` の `encodeURIComponent`、またはアプリに同梱した小さな Swift のヘルパー）。アプリ側は `URLComponents` の `queryItems` で取り出す、と明記する。検証に「空白・日本語・`#`・`&` を含むパス」を足す

## P2
- `Phase 1 > 2` — `memode://` と `memode-dev://` を Debug と Release で出し分けることが、project.yml の項目に書かれていない / dev 版と常用版が同じスキームを取り合い、どちらのアプリが開くか分からなくなる / ビルド設定（例: `MEMODE_URL_SCHEME`）を Debug と Release で分け、Info.plist の `CFBundleURLTypes` から参照する、と Phase 1 > 2 に足す
- `Phase 6 > 4` — URL スキームだけで開くと、どのアプリが開くかは LaunchServices に任せることになる / `build/` や DerivedData に残った古い `.app` も同じスキームを登録しているので、古いビルドが開くことがある / スクリプトは `open -b <bundle id> 'memode://open?path=...'` のように bundle id も指定する（URL なら存在しないパスでもエラーにならない）
- `Phase 6 > 4` — URL スキームは、ブラウザのリンクなど外部からも叩ける / 悪意のあるリンクで `path=/` のようなディレクトリを渡されると、登録フォルダに入ってしまい、Cmd+P が重い走査を始める / ディレクトリを登録フォルダに入れるのは、確認を挟むか、ホームディレクトリより下だけに限る
